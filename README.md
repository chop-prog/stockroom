# Stockroom

REST API склада: клиенты резервируют товар, неоплаченный резерв истекает и возвращается на склад, а один и тот же товар нельзя продать дважды.

_English: a Spring Boot REST API for reserving stock. Atomic SQL updates make overselling impossible; a test fires 100 concurrent requests at the last 10 units._

Java 21 · Spring Boot 3.5 · Spring Data JPA · H2 · JUnit 5 · MockMvc

## Что здесь интересного

**Товар нельзя продать дважды.** Проверка остатка и списание выполняются одним SQL-запросом (`update ... where available >= :quantity`), поэтому конкурирующие запросы упорядочивает база данных. Если сначала прочитать остаток, а потом сохранить новый, два запроса могут увидеть одно и то же число и продать лишнее.

**У резерва один исход.** Подтверждение, отмена и истечение срока — условные обновления, которые срабатывают только для статуса `ACTIVE`. Если они столкнутся, выиграет ровно одно, и товар вернётся на склад не больше одного раза.

**Время подставляется в тестах.** Срок резерва проверяется переводом часов, без ожидания.

## API

| Запрос | Что делает |
|---|---|
| `POST /api/products` | Создать товар |
| `GET /api/products/{id}` | Товар и доступный остаток |
| `POST /api/products/{id}/restock` | Пополнить склад |
| `POST /api/reservations` | Зарезервировать, `409` если не хватает |
| `GET /api/reservations/{id}` | Посмотреть резерв |
| `POST /api/reservations/{id}/confirm` | Подтвердить до истечения срока |
| `DELETE /api/reservations/{id}` | Отменить и вернуть товар |

Ошибки возвращаются в формате RFC 7807 (`application/problem+json`).

## Запуск

Нужны JDK 21 и Maven. База H2 находится в памяти.

```bash
mvn verify
mvn spring-boot:run
```

## Тесты

14 тестов проходят через настоящий HTTP-слой и базу. Среди них: 100 одновременных запросов на последние 10 единиц, гонка подтверждения и отмены, истечение срока и возврат товара ровно один раз.

## Ограничения

Учебный проект: нет авторизации, а H2 в памяти теряет данные при перезапуске. Для рабочей системы нужна PostgreSQL и миграции.
